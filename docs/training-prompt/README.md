# Tiny drone detection and tracking training project

Train a tiny-drone detector with camera-motion-compensated residuals fused at the YOLO input, adapt SAM2 to drone imagery, and test whether each component improves detection and subsequent video tracking. This is a **fresh training project**, starting from generic pretrained YOLO and official SAM2 weights. All experiment outputs in this plan are to be generated by the executing team.

The primary detector is **YOLO11m-P2 with RGB + one numerical residual channel**. SAM2 first provides a box-prompted mask refiner; a separately implemented box-supervised classification/regression head is needed for semantic candidate detection. The full video tracker is a subsequent integration stage, with explicit target loss and reacquisition handling.

## Scope and implementation status

| Component | Role | Status at project start |
|---|---|---|
| A: RGB YOLO11m-P2 | Matched detector baseline | Model-building reference provided; fresh training required |
| B: RGB + D YOLO11m-P2 | Main proposed detector | Input-fusion reference provided; fresh training required |
| SAM2.1 Large teacher | Generate training-only pseudo-masks from boxes | Reference command provided |
| SAM2.1 Tiny decoder adaptation | Refine automatically proposed boxes | Reference command provided; fresh training and validation required |
| SAM2 classification and box regression head | Classify drone candidates and refine their boxes | T08 implementation required |
| Unified A/B trainer and formal evaluator | Apply identical data and selection rules | T04/T09 implementation and verification required |
| Video association, memory, and reacquisition | Produce stable tracks from model outputs | T12-T14 integration and sequential evaluation required |

See [reference_implementation/README.md](reference_implementation/README.md) for the provided code components. A configuration template is a specification, not a completed training launcher. The experiment must be able to report a negative or inconclusive result; an improvement is a research objective, not a guaranteed acceptance outcome.

## Data and initialization

- NewDJI28: 28 raw videos and bounding-box annotations; unresolved empty annotations are excluded from training negatives.
- ARD100 and the existing DJI source pool: inspect the inventories, build new reproducible manifests, and preserve source-video separation.
- Anti-UAV and NPS: candidate external evaluation domains under an explicit protocol. Strict domain holdout requires excluding the target domain from training and tuning.
- AOT and TriCross-D2D: optional additional domains only if their data, labels, and inclusion rules are explicitly frozen before training.
- Initialization: use the same generic YOLO11m weights for the A/B pair and official SAM2.1 Large/Tiny weights for their respective roles. Record content hashes.

Raw videos, annotations, dataset manifests, and weight binaries are external assets. Their inventory and acquisition information are included; they are not Git-tracked payloads. [07_DELIVERY_INDEX.md](07_DELIVERY_INDEX.md) describes the required receipt checks.

## Scientific requirements

- Split by capture group or source video before producing any derivatives.
- Preserve RGB evidence when compensation is invalid or target motion is weak.
- Use numerical compensated residuals, not colorized motion-video frames.
- Compare A/B with the same P2 architecture, data order, training-update limit, augmentation, seeds, checkpoint selection, and evaluator.
- Calibrate thresholds on validation data and freeze them before testing.
- At evaluation and deployment, SAM prompts come from model predictions. Ground-truth prompts are allowed only in separately labeled oracle diagnostics.
- Distinguish detection improvement, segmentation behavior, and tracking performance. Bounding boxes alone do not support true segmentation Dice/IoU claims.
- Save recoverable checkpoints during each new run, and verify interruption recovery before a long run.

## Design reference

The [project presentation](https://docs.google.com/presentation/d/1IgUQSiuSl5q4D-uDwLS9rn4-uysi9vwYSHW4p_vmyH4/edit) provides the optical-flow, SAM adaptation, and temporal-consistency direction. This specification turns that direction into assignable work. The training core covers the detector and SAM components; Action Bank and video memory belong to the explicit tracking extension. The 3D/RTK workstream is outside this training project.

Reference methods inform the design; their appearance in the presentation does not mean the corresponding component is already implemented or validated here.
